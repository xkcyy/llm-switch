# 变更记录

按主题记录产品与实现的演进。版本号为构建时注入到 EXE 的版本（`--version` 可查）。

## 2026-09-22

### Trae SOLO 接入：高级配置与健壮性（0.6.2）

- **填写「高级配置」**：以前添加模型只填了 API 格式 / 请求地址 / 模型 ID / 显示名 / API Key，Trae 里高级配置全空。现在会按 LLM Switch 的模型元数据写入：**上下文窗口（输入）** ← `context_window`、**思考模式=开启** ← `reasoning.levels` 非空、**图片输入** ← 能力标注或测试反推；输出窗口、工具调用轮数、采样参数、模型系列保持 Trae 默认。
- **图片输入用 Trae 自己的测试反推**：连通性测试发的是带图片的请求，纯文本模型必然报「不支持图片输入」。现在遇到这个提示会先把「支持图片输入」改成**不支持**并重试一次——测试随之通过，模型带着正确能力注册（实测 `ocg/glm-5.3` 从「测试失败→直接保存」变成「测试通过」）。
- **删除前先关弹窗**：若界面上还停着「供应商选择」或添加表单，表格会被盖住导致点不到行内删除图标；删除前先关掉浮层并确认仍在模型设置页。
- 核对方式：Trae 本地缓存里 `prompt_max_tokens` / `thinking_enable` / `multimodal` 分别对应上下文窗口 / 思考模式 / 图片输入。

### Trae SOLO 接入：修正与增强（0.6.1）

反馈驱动的一轮修正（都是真机复现后改的）：

- **修掉「删不掉不一致模型」**：根因是扫描竞态——Trae 的设置页先渲染壳、表格数据后到，读早了会得到 0 行，于是「明明有 4 个多余模型」被判成「没有多余的」，同步也会误判。现在要求**连续两次读到的行数一致**才采信（`waitTableRows`），超时且一行都没有则明确报错而不是静默放过。
- **「接入」改为双向对齐**：补齐缺失 + 删除与代理不一致的自定义模型 + 结尾复核并给出一句如实的结论（例如「Trae 现有自定义模型 16 个：本次新增 0、删除 4；已与本地代理一致」）。因此原来的「断开接入」按钮去掉——清理已经包含在接入里。
- **新增「重新排序」**：Trae 的模型列表是「新加的排最前」，要得到「同供应商相邻」的顺序只能重建。该按钮会删掉全部代理模型后**按逆序重新添加**，使最终展示顺序等于代理配置顺序；由于每个模型都会重跑一次连通性测试，慢上游可能要几分钟，界面上有明确提示与确认。实测 16 个模型重建约 6 分钟，最终顺序为 `ds/* → ocg/* → km/*`，完全一致。
- **顺序不匹配会被如实报告**：新增模型后（新模型落在最前面）接入会提示「顺序未对齐，可点重新排序」，而不是假装一切正常。

### Trae SOLO 一键接入（页面版，已真机验证）

在「脚本版」验证通过后，把 Trae 接入做成了产品能力：

- **页面**：新增「接入 Trae SOLO」页——一个「一键接入」按钮 + 一个「断开接入」按钮；扫描差异是内部动作，用户只需要知道点完之后 Trae 的模型与本地代理一致。
- **Go 内置 CDP 驱动**：新增 `internal/cdp`（极简 CDP 客户端：Runtime.evaluate + Input.dispatchMouseEvent/Escape）与 `internal/trae`（路径探测、argv.json 调试端口、界面驱动、任务进度）。只新增 `github.com/gorilla/websocket` 一个依赖，保持单文件 EXE。
- **差异计算**：以 Trae 设置页表格为服务端真值（实测 `state.vscdb` 字节扫描有 11 个假阳性、纯 Go 读 SQLite 代价过大），扫描一次约 4 秒，只对缺失项执行添加。
- **健壮性**（都是真机踩出来的）：
  - 成功判定用「弹窗关闭」+ 列表回读，不信 Toast（Toast 会残留导致误判「下一条已成功」）；
  - 「已存在」判定只看添加弹窗内部（整页扫描会被聊天记录里的「已存在」字样误伤）；
  - 行扫描要求带删除图标，避免把聊天区的 Markdown 表格当成模型行；
  - 连通性测试带图片输入，纯文本模型必然失败 → 自动走官方「直接保存」；
  - Trae 未运行则带调试端口拉起，正在运行但没端口则引导重启（`--configure-argv` 语义内置）。
- **测试**：`internal/trae` 覆盖差异计算与 argv.json 读写；需要真实 Trae 的端到端用例用 `TRAE_E2E=1` 开启（连上 Trae → 打开模型设置页 → 加一个探针模型 → 校验 → 删除）。
- **实测**：16 个模型全部注册；从 Trae 删掉 `ocg/hy4-preview` 后点同步，页面自动补回（走「直接保存」），代理日志出现 `entry=chat model=ocg/hy4-preview … status=404`（上游本身 404，属预期）。

### Trae SOLO 接入（脚本，已真机验证）

起因：希望 TRAE SOLO 也能用上本机代理的模型。原方案（外部给的思路）是「CDP + Playwright 驱动官方 UI 添加自定义模型」，按此做了可行性分析与真机验证，结论可行并修正了若干坑：

- **调试端口可常驻**：`remote-debugging-port` 在 `argv.json` 白名单里，一次写入永久生效（无需每次换快捷方式启动）。
- **接口确认**：自定义模型由服务端注册（应用内协议 `chat/add_custom_model`，另有 `update` / `test_custom_model_connection`），本地 `state.vscdb` 只是缓存；`client_connect = true`，官方文案说明只支持本地环境。
- **三处关键修正**：① 请求地址应填 `http://127.0.0.1:8317/v1`（「完整 URL」默认关闭，Trae 会补 `/chat/completions`）；② 成功判定要用「弹窗关闭」，Toast 会残留导致误判；③ 连通性测试带图片输入，纯文本模型必然失败，需用官方「直接保存」注册。
- **实测证据**：代理日志 `entry=chat model=ds/deepseek-flash … status=200`；显示名与模型 ID 故意写成不同值，确认请求用的是模型 ID。
- **实测结果**：16 个模型全部注册成功（少数连通性测试通过，多数因「测试请求带图片输入」由脚本点官方「直接保存」注册）；再跑 `--dry-run` 输出「全部已存在，无需处理」。
- **交付**：`tools/trae-solo/sync_models.py`（幂等、可 `--dry-run`、可只处理指定模型、失败留截图），分析文档见 `docs/design/Trae-SOLO-接入分析与方案.md`。

### 转换层修复与供应商多协议（0.5.x）

起因：Codex 在 Responses→Chat 链路上报 `An assistant message with 'tool_calls' must be followed by tool messages responding to each 'tool_call_id'`。定位为协议转换缺陷，修复并顺手补齐协议选择能力：

- **并行工具调用合并**：`ResponsesToChatRequest` 把连续的 `function_call` / `custom_tool_call` 合并到同一条 assistant 消息，工具结果按 `call_id` 配对并紧跟其后；缺结果补占位、孤立结果丢弃并写入告警。修掉了「Codex 一轮发两个工具调用必然 400」的问题。
- **思考内容回传（DeepSeek/OpenCode Go）**：代理按「供应商 + 模型 + 工具调用 ID」缓存上游 `reasoning_content`（30 分钟），构造带工具的 assistant 消息时回填；冷缓存对已知思考型供应商写空字符串，避免 `The reasoning_content in the thinking mode must be passed back to the API`。
- **自定义工具桥接**：Codex 桌面版声明为 `custom` 的工具（`exec`、`apply_patch` 等自由文本工具）降级为「单 `input` 字符串」函数工具传给 Chat 上游；上游返回同名调用时还原为 `custom_tool_call`（含 `response.custom_tool_call_input.*` 事件）。此前这些条目会被整对静默丢弃。
- **供应商多协议 + 原生直通优先**：`providers[].protocols` 有序多选（`protocol` 保留为兼容字段，恒等于首项）。选择规则确定：入口协议命中即直通（保留 `store`/`include`/`prompt_cache_key`/custom tools 等原生特性）；未命中按顺序转换；都不行则返回明确错误。`models[].protocol` 仍可把个别模型固定为单协议。
- **连接测试按协议探测**：供应商/模型测试按协议列表逐个探测，返回实际可用的协议（界面提示「连接正常 · responses」）。
- **可观测性**：代理记录与日志新增 `upstream`/`converted`/`warnings`，直通与转换可区分；转换降级会告警。
- **文档**：技术设计方案 §9 补充协议选择规则、转换实现约定与限制。

实测验证：用真实 DeepSeek 与 OpenCode Go 复现原 400（含并行调用的历史），合并后仍报 `reasoning_content` 缺失，补回填后 200；三组请求均通过。

### 上游兼容与预置修正（0.4.x）

- **预置地址按官方文档修正**：DeepSeek 改为 `https://api.deepseek.com`（不带 `/v1`）；OpenCode Go 改为 `https://opencode.ai/zen/go/v1`；OpenAI / Anthropic 保持带 `/v1`。
- **新增预置 KmAiModelHub**：`https://aimodelhub.ai.kmsoft.com.cn/v1`，默认协议 `responses`（实测该地址同时支持 Chat 与 Responses）。
- **上游请求头约定**：统一 `User-Agent: llm-switch/<版本>`；会话标识 `x-opencode-session` 优先透传客户端会话头（含 Codex 的 `session_id`），缺失时用「模型 + 首条用户消息」生成稳定 ID。修复了 OpenCode Go 报 `Request is missing x-opencode-session` 的问题。
- **模型级协议覆盖**：同一网关不同模型可走不同端点（OpenCode Go：GLM/Kimi 走 chat、Qwen/MiniMax 走 messages、Grok/GPT-Luna 走 responses），导入时自动给出建议。
- **Codex 显示名统一**：模型清单的 `display_name` 固定等于 `slug`（`供应商ID/模型ID`），Codex 模型列表与请求名一致，避免同名模型分不清来源。
- **交互修复**：
  - 二次"从上游同步模型"弹窗关不掉：同步按钮加 loading 去重、每次同步用新弹窗实例、loading 提示改为 finally 销毁、导入重复模型逐条跳过并提示。
  - 修改供应商信息后模型列表被清空：供应商 ID 变更时前端同步重写本地模型的归属与请求名，并跟随选中项。
  - 添加模型弹窗过长被遮挡：弹窗主体限高可滚动，底部按钮始终可见。

### 配置自愈与容错（0.3.3）

- 启动时自动修复不一致数据：孤儿模型移除、供应商缺 ID 补齐、非法协议回退、重复项去重、默认模型失效回退。
- 单点数据异常不再阻断整体：`/api/codex` 返回告警而非报错；前端改为逐项加载，部分失败只提示、其余功能可用。
- 总览页展示"已自动修复 N 项配置问题"及明细。

### 无控制台黑框（0.3.2）

- 打开浏览器/目录从 `cmd /c start` 改为 Windows `ShellExecute`，双击 EXE 不再闪黑框。

## 2026-09-21

### 供应商 ID 语义（0.3.x）

- 供应商 `id` 可在界面配置，并成为模型映射的定位项与请求名前缀（`供应商ID/模型ID`，兼容按名称匹配）。
- 存储层保留上游原始模型 ID 与名称，只有对外请求名拼接供应商 ID；模型 ID 允许包含 `/`（如 `Qwen/Qwen3.6-35B-A3B`）。
- 密钥查看闭环：列表脱敏显示，编辑弹窗点眼睛按需拉取完整值，输入即替换、不动即保留。

### 界面框架梳理（0.2.1 ~ 0.2.2）

- 顶栏压缩到 60px 并去掉重复信息；侧栏品牌区与顶栏对齐、底部改为菜单式"配置目录"与版本行。
- 接入 Codex 已接入状态由大 Result 改为单行状态卡；供应商长地址移到正文；表格表头不换行、窄屏自动上下堆叠。
- 供应商/模型弹窗字段逐行；模型弹窗拆分为「上下文窗口（输入）」与「最大输出（输出窗口）」，带 128K/256K/512K/1M 等快捷档位。

### 前端重做（0.2.x）

- 界面从原生 HTML 迁移到 Vite + React + Ant Design（`web/` 工程，构建产物由 Go 内嵌）。
- 交互按"默认即正确"设计：选预设 + 粘贴 Key 即可；保存后自动测试、自动拉取模型、元数据自动补全、默认全选导入；首个模型自动成为默认模型；Codex 一键接入、自动同步默认开启。
- 模型元数据在线补全（models.dev + 本地缓存），命名空间优先、不跨供应商猜测。

### 首个可运行版本（0.1.0）

- Go 后端：供应商/模型管理、本机代理（Chat / Responses / Messages）、模型名称映射、协议转换（含 SSE 流式）、Codex 配置生成与同步、系统托盘、开机启动、单实例、日志滚动。
- 管理面 REST API 与令牌保护；配置存储原子写入。
- 单元与集成测试：映射规则、协议转换、代理端到端、Codex 配置合并与目录生成。
