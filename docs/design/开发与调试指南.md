| 项目 | 内容 |
|---|---|
| 文档版本 | 1.0 |

## 1. 代码结构

```text
cmd/llm-switch/         程序入口：参数解析、单实例、托盘、生命周期
internal/
  admin/                管理面 REST API（/api/*）与前端托管（含令牌注入）
  app/                  启动编排、配置变更订阅、Codex 自动同步
  autostart/            开机启动（HKCU Run，--silent 启动）
  buildinfo/            版本与 User-Agent 标识
  codex/                config.toml / auth.json / 模型清单生成与写入、断开接入
  config/               config.json 存储、原子写入、启动自愈（Sanitize）
  instance/             单实例互斥体
  logx/                 按天滚动日志
  metadata/             模型元数据在线补全（models.dev，本地缓存）
  provider/             供应商与模型领域服务（连接测试、模型测试、拉取模型）
  proxy/                代理服务、映射索引
    protocol/           Chat / Responses / Messages 协议转换（请求、响应、SSE）
  tray/                 系统托盘与图标生成
  winutil/              ShellExecute 封装（无控制台打开浏览器/目录）
web/                    前端工程（Vite + React + antd），构建到 web/dist 供内嵌
prototype/              交互原型（独立运行，模拟数据）
testdata/mock-upstream/ 本地联调用的模拟上游
docs/                   文档
screenshots/            界面截图
```

## 2. 构建

### 2.1 一键构建（推荐）

```powershell
# 前端构建 → go test → 打包 EXE
powershell -ExecutionPolicy Bypass -File build.ps1 -Version 0.4.2

# 前端已构建过，只跑测试与打包
powershell -ExecutionPolicy Bypass -File build.ps1 -SkipUI -Version 0.4.2
```

产物：`dist/LLM-Switch.exe`（当前约 9 MB，限制 50 MB）。

### 2.2 分步构建

```powershell
cd web; npm install; npm run build      # 生成 web/dist
cd ..; go build -trimpath -ldflags "-s -w -H=windowsgui -X main.version=0.4.2" -o dist/LLM-Switch.exe ./cmd/llm-switch
```

- `-H=windowsgui` 必须保留：否则双击会出现控制台窗口。
- 前端改动后必须重新 `npm run build`，否则内嵌的是旧界面。

### 2.3 快速自检

```powershell
# PE 子系统应为 2（Windows GUI）
$b=[IO.File]::ReadAllBytes('dist\LLM-Switch.exe'); $o=[BitConverter]::ToInt32($b,0x3C)+24
[BitConverter]::ToUInt16($b,$o+68)   # 期望 2
```

## 3. 运行与参数

```powershell
.\dist\LLM-Switch.exe            # 托盘常驻 + 自动打开管理页
.\dist\LLM-Switch.exe --silent   # 静默启动（开机启动使用，不打开浏览器）
.\dist\LLM-Switch.exe --no-tray  # 调试：不启动托盘
.\dist\LLM-Switch.exe --version  # 输出版本号
```

| 运行时文件 | 位置 |
|---|---|
| 配置 | `%USERPROFILE%\.llm-switch\config.json` |
| 日志 | `%USERPROFILE%\.llm-switch\logs\app-YYYY-MM-DD.log` |
| 元数据缓存 | `%USERPROFILE%\.llm-switch\metadata\modelsdev.json` |
| Codex 配置 | `%USERPROFILE%\.codex\config.toml`、`auth.json`、`llm-switch-models.json` |

管理界面：`http://127.0.0.1:8318`；代理：`http://127.0.0.1:8317`。

## 4. 本地联调（模拟上游）

```powershell
go run ./testdata/mock-upstream -addr 127.0.0.1:9911
```

在界面里新增供应商时选任意预设，把「接口地址」改为 `http://127.0.0.1:9911/v1`，API Key 随便填（默认校验 `sk-test`）。该模拟上游提供：

- `GET /v1/models`：返回 deepseek-chat / glm-5.3 / qwen3.8-max / grok-4.7 等模型
- `POST /v1/chat/completions`：支持流式与非流式
- `POST /v1/responses`：非流式响应

联调完整链路：新增供应商 → 自动测试 → 拉取模型（含协议建议）→ 导入 → 一键接入 Codex → 用 Codex 或 curl 调代理。

```powershell
# 直接压代理（Responses 入口）
curl.exe -s http://127.0.0.1:8317/v1/responses -H "Content-Type: application/json" -d "{\"model\":\"opencode-go/glm-5.3\",\"input\":\"hi\"}"
```

## 5. 测试

```powershell
go test ./...          # 全部单元与集成测试
go vet ./...; gofmt -l .
```

覆盖范围：

| 包 | 覆盖内容 |
|---|---|
| `internal/config` | 原子写入、并发通知、失败不污染内存、**启动自愈**（孤儿模型、默认模型回退、协议纠正） |
| `internal/proxy` | 映射规则全分支、代理端到端（httptest 模拟上游）、错误转换、**模型级协议覆盖**、**会话头透传与 UA** |
| `internal/proxy/protocol` | Responses↔Chat↔Messages 请求/响应/SSE 事件转换 |
| `internal/codex` | 模型清单生成与校验、config.toml 合并（保留用户键）、默认模型回退、真实 Codex 校验导出 |
| `internal/trae` | 差异计算（SplitDiff）、argv.json 调试端口读写与备份、自定义模型 vendor 判定；真实 Trae 的端到端用例见下 |

真实 Trae 端到端（可选，需要 Trae 正在运行且调试端口可用）：

```powershell
$env:TRAE_E2E = "1"
go test ./internal/trae -run E2E -v            # 扫描模型列表 + 加/删探针模型
$env:TRAE_E2E_TARGET = "ocg/hy4-preview"
go test ./internal/trae -run TestE2EDeleteTarget -v   # 从 Trae 删掉指定模型（验证补差异用）
```

真实 Codex 校验（可选，验证生成的目录能被 Codex 解析）：

```powershell
$env:LLM_SWITCH_DUMP_DIR = "$env:TEMP\catalog-check"
go test ./internal/codex -run TestDumpForCodexValidation -v
$env:CODEX_HOME = "$env:TEMP\catalog-check"; codex debug models | Select-Object -First 1
```

## 6. 常见问题

| 现象 | 原因与处理 |
|---|---|
| 双击 EXE 闪黑框 | 已修复（改用 ShellExecute 打开浏览器/目录）；若出现，确认构建带 `-H=windowsgui`，且没有遗留的 `cmd /c start` 调用 |
| 双击后没反应 | 已有实例在运行（单实例互斥）：会打开管理页后自动退出；从托盘菜单确认 |
| 管理页提示"令牌无效" | 管理面令牌每次启动随机生成，请从托盘「打开管理页」进入 |
| 端口被占用 | 代理 8317 / 管理 8318 被占时会明确报错；在设置页改端口，代理端口变更会触发 Codex 同步 |
| Codex 里没生效 | Codex 只在启动时读取 `config.toml` 与模型清单，改完请重启 Codex |
| 界面提示"已自动修复 N 项配置问题" | 启动自愈修复了不一致数据（默认模型失效、孤儿模型等），明细在提示里 |
| 默认模型失效导致同步失败 | 已改为自动回退到第一个可用模型并给出告警，不再阻断 |
| 配置写坏了 | 程序不做快照/回滚：删除 `config.json` 会重建默认配置；排查前建议先复制一份 |
| 元数据没补全 | 该模型不在 models.dev 收录范围内（或网络不可用）；可手动填写上下文窗口/推理档位 |

## 7. 发布检查清单

1. `build.ps1` 通过（前端构建 + 测试 + 打包）。
2. EXE 体积 < 50 MB，PE 子系统 = 2（GUI）。
3. 双击启动：无黑框、托盘出现、管理页自动打开。
4. 用真实 Codex 验证：一键接入 → 重启 Codex → 模型列表显示 `供应商ID/模型ID` → 发起一次对话。
5. 覆盖安装前确认用户配置无需迁移（`schema_version` 兼容）。
