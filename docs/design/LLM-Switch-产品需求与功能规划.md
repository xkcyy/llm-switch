# LLM Switch 产品需求与功能规划

| 项目 | 内容 |
|---|---|
| 文档版本 | 1.6 |
| 文档状态 | 规划基线 |
| 更新日期 | 2026年9月22日 |
| 产品形态 | Windows GUI + 本地模型代理 |
| 首发范围 | MVP |

## 1. 产品概述

LLM Switch 面向使用多个模型供应商和 Codex 的个人开发者，统一管理供应商和模型，并通过本地代理向 Codex 提供统一模型入口。

用户在 LLM Switch 中配置供应商和模型后，代理根据请求中的模型名称识别供应商和真实模型，并将请求转发到对应上游。Codex 通过专属配置页面接入代理：页面只提供一个“自动同步”开关，关闭时按 cc-switch 风格手动填写请求地址、默认模型和配置文件，开启时由 LLM Switch 自动填写并写入对应值。

## 2. 产品目标

1. 统一维护多个供应商、模型、接口格式和供应商认证信息。
2. 通过一个本地代理入口向 Codex 提供模型服务。
3. 用明确、可诊断的模型名称映射规则完成请求转发，不引入路由对象。
4. 通过 GUI 完成代理控制、模型管理、Codex 配置和模型测试。
5. 交付单个不超过 50 MB 的 Windows EXE，配置和状态存储在当前用户目录。

## 3. 规划边界

### 3.1 MVP 范围

| 项目 | 范围 |
|---|---|
| 操作系统 | Windows |
| 交互方式 | GUI；系统托盘与开机启动 |
| 目标 Agent | Codex |
| 代理协议 | OpenAI API、Responses、Anthropic Messages |
| 代理访问 | 仅本机；代理启动后默认无需 API Key |
| 模型管理 | 供应商模型配置、模型增删、模型测试 |
| 模型映射 | 基于请求模型名称匹配供应商和真实模型 |
| Agent 配置 | Codex 配置页；自动同步开关，关闭时手动配置 |
| 供应商类型 | 预置类型和自定义类型；首批包含 KmAiModelHub、OpenCode Go、DeepSeek、OpenAI、Anthropic |
| 配置存储 | 当前 Windows 用户目录 |
| 发布形式 | 单文件 EXE，文件大小不超过 50 MB |
| 供应商密钥 | 作为供应商配置字段保存；允许明文存储，界面默认脱敏 |

### 3.2 暂不支持

- macOS、Linux、CLI。
- Claude Code 配置同步；MVP 先不支持。
- Trae、OpenCode 等其他 Agent 的配置同步。
- 自定义路由、内置路由及其他路由对象。
- 局域网访问；当前代理仅监听本机地址。
- 独立的凭据管理页面或凭据管理模块。
- cc-switch 或其他工具的配置导入（仅参考其 Codex 配置页的交互形式）。
- 团队协作、云端控制台和云端中转。
- 计费、额度、成本核算。
- 故障转移、负载均衡和按成本自动选模。
- 模型训练、知识库、提示词管理和 Agent 编排。

## 4. 用户与核心场景

| 用户 | 核心场景 | 期望结果 |
|---|---|---|
| 多供应商开发者 | 维护多个供应商和模型 | 一处配置、统一测试 |
| Codex 用户 | 为 Codex 配置统一代理 | 开启自动同步，或手动编辑配置文件 |
| 调试用户 | 定位连接或模型配置问题 | 通过连接测试和模型测试返回明确错误 |

## 5. 核心对象与状态

| 对象 | 定义 | 主要字段 |
|---|---|---|
| 供应商 | 一个外部模型服务连接 | 名称、预置类型、地址、接口格式、认证字段、状态 |
| 模型 | 供应商提供的真实模型 | 供应商 ID、模型 ID、显示名称、能力、状态 |
| 代理 | 对外提供统一访问地址的本地服务 | 本机地址、端口、协议、运行状态 |
| Agent 配置 | Codex 接入本地代理的配置方式 | Agent 类型、自动同步开关、请求地址、默认模型、配置文件内容 |

状态：

- 供应商/模型：未验证、可用、异常、停用。
- 代理：已停止、启动中、运行中、异常。

## 6. 功能规划

### 6.1 供应商管理

- 新增、编辑、删除、启用和停用供应商。
- 新增供应商时支持选择预置供应商类型：KmAiModelHub、OpenCode Go、DeepSeek、OpenAI、Anthropic，以及自定义类型。
- 预置类型用于预填供应商名称、ID、接口格式、默认地址和可用配置项；用户可以在保存前修改可编辑字段。
- 配置供应商 ID、名称、接口地址、接口格式和认证字段。
- 支持 OpenAI API、Responses、Anthropic Messages。
- 支持连接测试，并显示认证、网络、限流、地址和协议错误。
- 删除存在关联模型的供应商时，显示影响范围并要求确认。
- 供应商 ID 是模型名称映射的定位项和请求名前缀，在界面上可配置；不允许包含 `/`。供应商名称仅用于展示。

### 6.2 模型管理

- 手工添加供应商模型。
- 供应商支持时获取模型列表。
- 保存真实模型名称、显示名称、能力和状态。
- 支持为单个模型指定接口协议（默认跟随供应商），用于同一网关不同模型使用不同端点的场景。
- 支持模型调用测试。
- 支持新增、编辑、停用和删除模型。
- 模型新增或删除后，向已开启自动同步的 Codex 配置更新模型清单；默认模型被删除或停用时，同步更新默认模型。
- 停用模型后，不得接受以该模型为目标的新请求。
- 删除模型时，显示该模型在 Codex 模型清单中的影响。

### 6.3 供应商认证字段

认证信息不是独立功能模块，仅作为供应商配置的一部分：

- 支持 API Key、Bearer Token 和供应商所需的自定义认证字段。
- 认证字段允许明文存储在当前用户目录配置中。
- 界面默认显示脱敏值；点击查看图标显示完整内容，再次点击恢复脱敏。
- 完整认证信息不得出现在日志、调用记录和 Agent 配置文件中。
- 代理对本机客户端默认不要求 API Key；供应商认证信息仅用于访问上游服务。

### 6.4 本地代理

- 启动、停止和重启代理。
- 默认监听本机地址，仅允许当前设备访问。
- 代理启动后，客户端默认无需 API Key、访问令牌或其他代理认证信息即可请求。
- 显示运行状态、监听地址、端口、支持协议和当前请求情况。
- 支持 OpenAI API、Responses、Anthropic Messages。
- 支持流式响应、工具调用、请求取消和错误返回。
- 根据模型名称映射规则选择供应商和真实模型。
- 代理停止后不得继续接受新请求。
- 协议不匹配、模型不存在、模型停用或上游失败时返回明确错误。

### 6.5 模型名称映射

代理不使用内置路由、自定义路由或其他路由对象。代理直接根据客户端请求中的 `model` 值匹配本地模型目录。

#### 6.5.1 标准名称

模型对外名称支持以下形式：

```text
供应商ID/模型ID
```

示例：

```text
deepseek/deepseek-chat
openai/gpt-4.1
anthropic/claude-sonnet-4
```

#### 6.5.2 匹配顺序

1. 去除请求 `model` 首尾空白；空值直接返回模型参数错误。
2. 如果名称包含 `/`，以第一个 `/` 为分隔符：
   - `/` 前的部分作为供应商 ID（也兼容供应商名称）。
   - `/` 后的全部内容作为模型 ID；模型 ID 内部允许继续包含 `/`。
   - 先匹配已启用的供应商，再在该供应商下精确匹配已启用的模型。
3. 如果名称不包含 `/`，在所有已启用供应商中精确匹配模型 ID：
   - 只有一个匹配结果时使用该模型。
   - 匹配到多个供应商时返回名称歧义错误，并提示使用 `供应商ID/模型ID`。
   - 没有匹配结果时返回模型不存在错误。
4. 匹配使用去除首尾空白后的完整字符串，不进行模糊匹配、自动纠错或默认供应商回退。
5. 供应商和模型的显示名称不等于真实匹配 ID 时，仅在用户明确配置了同名真实模型后参与匹配。

#### 6.5.3 匹配优先级与结果

| 情况 | 处理 |
|---|---|
| `provider/model` 唯一匹配 | 转发到指定供应商的指定模型 |
| `model` 唯一匹配 | 转发到唯一命中的供应商模型 |
| `model` 命中多个供应商 | 拒绝请求，返回模型名称歧义 |
| 供应商不存在或停用 | 拒绝请求，返回供应商不可用 |
| 模型不存在或停用 | 拒绝请求，返回模型不可用 |
| 请求名称为空 | 拒绝请求，返回缺少模型名称 |
| 名称包含多个 `/` | 第一个 `/` 分隔供应商，其余内容属于模型名称 |

代理日志必须保存请求模型名称、匹配到的供应商和真实模型名称；匹配失败时保存失败阶段和错误原因。

#### 6.5.4 协议处理

- 代理先根据请求入口识别 OpenAI API、Responses 或 Anthropic Messages。
- 模型映射成功后，根据供应商配置的上游接口格式发送请求。
- 客户端协议与上游协议一致时，按原协议转发。
- 客户端协议与上游协议不一致时，仅在 MVP 已支持对应转换的范围内转换；不支持时返回协议不兼容错误。
- 协议转换不得改变模型名称映射结果；错误响应必须保留可诊断的协议和上游信息。

### 6.6 Agent 配置

Agent 配置按 Agent 类型独立管理，MVP 只提供 Codex 配置；Claude Code 等其他 Agent 暂不支持。

Codex 配置页只保留一个“自动同步”开关：

- 手动与自动共用同一套生成与写入逻辑，区别仅在触发方式。
- 关闭（手动模式）：参考 cc-switch 的 Codex 配置页，展示并允许编辑 API Key、API 请求地址、默认模型，以及 auth.json（JSON）、config.toml（TOML）等配置文件内容；用户点击保存触发写入。
- 开启（自动模式）：同一套内容自动填写，模型新增或删除、默认模型或代理端口变更时自动触发写入。

配置页不展示检测状态、配置位置、代理地址、当前模型、模型同步范围、最近同步时间、同步结果和恢复入口。

### 6.7 Codex 配置

#### 6.7.1 默认配置方式

Codex 默认使用 config.toml（TOML）配置：

- 在 config.toml 中配置 model_provider 相关信息，包括模型供应商标识和请求地址；wire_api 使用 Codex 当前支持的 responses。
- 通过 model_catalog_json 指定模型清单文件；该文件由 LLM Switch 生成和维护，默认存放在 Codex 配置目录，清单内容为 LLM Switch 中当前可用的模型，并遵循 Codex 的模型目录（catalog）JSON 格式。
- auth.json（JSON）保存 Codex 使用的认证信息；本地代理默认不校验 API Key，自动模式下可写入占位值。

#### 6.7.2 页面行为

- 自动同步关闭时：页面展示请求地址、默认模型和配置文件内容，支持编辑、格式化和保存，点击保存触发写入。
- 自动同步开启时：与手动模式相同的内容自动填写并写入，无需手动保存。
- 自动同步开启后，模型新增或删除时自动更新模型清单文件；默认模型被删除或停用时同步更新 config.toml 中的模型字段。
- 自动同步至少在模型新增完成或模型删除完成后触发。
- 用户关闭自动同步后，后续模型增删不得自动修改 Codex 配置，但仍可手动编辑并保存。
- 配置写入失败时不改动原配置，并显示失败原因。

### 6.8 数据一致性与自愈

- 启动时检查配置一致性并自动修复：模型指向不存在的供应商、供应商缺少 ID、接口协议非法、重复条目、默认模型失效。
- 修复结果写入日志，并在概览页提示"已自动修复 N 项配置问题"及明细。
- 单条数据异常不得导致整体不可用：某一类数据加载失败时只提示该项，其余页面与功能仍可正常使用。
- Codex 配置生成遇到数据问题时自动回退（如默认模型失效时改用第一个可用模型）并给出告警，不阻断同步。
- 配置保存在单个 JSON 文件中，用户可在改动前自行复制备份；程序不提供快照与回滚功能。

## 7. GUI 信息架构

| 页面 | 主要内容 |
|---|---|
| 概览 | 代理状态、模型数量、Codex 自动同步状态、最近错误 |
| 供应商与模型 | 预置供应商类型、供应商连接、认证字段、模型列表和测试 |

| 代理 | 启停、端口、本机监听地址、支持协议和健康状态 |

系统托盘菜单提供：打开管理页、启动/停止代理、打开配置目录、开机启动开关和退出。

## 8. 核心业务流程

### 8.1 首次配置

选择预置或自定义供应商类型 → 填写接口地址和供应商认证字段 → 连接测试 → 添加或获取模型 → 启动本机代理 → 打开 Codex 配置页 → 手动填写并保存，或开启自动同步自动写入 → 完成真实调用。

### 8.2 模型增删与 Codex 自动同步

新增或删除模型 → 检查 Codex 自动同步开关 → 已开启时更新模型清单文件（必要时更新默认模型）→ 回读配置 → 显示写入结果。

### 8.3 模型请求转发

客户端发送请求 → 识别协议 → 读取 `model` → 按映射规则匹配供应商和模型 → 校验状态 → 按上游接口格式转发 → 返回结果并记录日志。

## 10. MVP 验收标准

1. Windows 上可使用单个不超过 50 MB 的 EXE 启动 GUI。
2. 用户可选择 KmAiModelHub、OpenCode Go、DeepSeek、OpenAI、Anthropic 等预置供应商类型，或选择自定义类型。
3. 用户可配置供应商接口地址、接口格式和认证字段，并完成连接测试。
4. 用户可添加或获取模型并完成模型测试。
5. 代理仅监听本机地址；启动后客户端无需 API Key 即可访问。
6. 代理支持 OpenAI API、Responses、Anthropic Messages。
7. 代理可按 `供应商ID/模型ID` 和无前缀模型 ID 完成确定性匹配。
8. 映射失败、名称歧义、供应商停用或模型停用时返回明确错误。
9. 代理支持流式响应、工具调用、请求取消和错误返回。
10. Codex 配置页提供自动同步开关；关闭时可手动填写 API 请求地址、默认模型和配置文件并保存。
11. 开启自动同步后，请求地址、默认模型和 model_catalog_json 模型清单自动写入 Codex 配置；新增或删除模型后清单自动更新。
12. 供应商认证字段在界面默认脱敏，点击后可查看完整内容；完整内容不出现在日志和调用记录中。
13. 供应商、模型、代理和 Codex 配置均可在 GUI 查看和操作。
14. 系统托盘可打开管理页并控制代理；开机启动可开启和关闭。
15. 单条配置数据异常时系统仍可用：启动自动修复并在界面提示明细，不阻断其他功能。

## 11. 风险与依赖

| 类型 | 内容 | 处理原则 |
|---|---|---|
| 风险 | Codex 配置格式变化 | 以 Codex 官方配置项为准；写入失败时不改动原配置 |
| 风险 | 同名模型跨供应商产生歧义 | 要求使用 `供应商ID/模型ID`，拒绝不确定请求 |
| 风险 | 供应商协议实现差异 | 模型测试和明确错误 |
| 风险 | 供应商认证信息被本机其他程序读取 | 明确明文存储风险，界面默认脱敏 |
| 风险 | 本机免密代理被本机其他进程访问 | 仅监听本机，不开放局域网，风险提示 |
| 依赖 | Codex 支持通过 config.toml 配置 model_provider 和 model_catalog_json | 以 Codex 实际支持的配置字段为准 |
| 依赖 | 上游对请求头的要求（如 OpenCode Go 需要会话标识与自定义 User-Agent） | 统一设置自有 UA，透传或生成稳定会话标识 |
| 依赖 | 供应商模型列表和接口能力 | 同时支持手工添加和测试 |
| 决策 | 暂不开放局域网访问 | MVP 只允许本机访问 |
| 决策 | 暂不引入路由对象 | 由模型名称直接完成供应商与模型匹配 |
| 决策 | 不提供诊断中心和分层检查 | 只保留供应商连接测试和模型调用测试 |
