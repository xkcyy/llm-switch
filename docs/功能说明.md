# 功能说明

| 项目 | 内容 |
|---|---|
| 文档版本 | 1.1 |
| 更新日期 | 2026年9月25日 |
| 适用版本 | 0.6.x |

## 一句话说明

LLM Switch 是一个 Windows 小工具：**把你在各家买的模型统一管起来，再通过一个本机地址提供给 Codex 使用**。配一次，之后新增或删除模型都会自动同步到 Codex，不用再手改配置文件。

## 它解决什么问题

- 模型来自多个供应商（企业网关、DeepSeek、OpenAI、Anthropic、OpenCode Go…），每家地址、密钥、协议都不一样。
- Codex 只能配置一个模型入口，切换供应商要改 `config.toml` 和模型清单，容易改错。
- LLM Switch 在中间加一个**只监听本机**的代理：Codex 永远只连它，由它按模型名转发到对应供应商。

## 核心能力

| 能力 | 说明 |
|---|---|
| 供应商管理 | 预置类型一键预填地址与协议；支持自定义；密钥默认脱敏、点眼睛查看完整值；连接测试给出明确错误（认证/网络/限流/地址/协议） |
| 模型管理 | 从上游一键拉取模型列表；上下文窗口、输出窗口、推理档位、图片输入自动补全；导入前可勾选；支持手动添加/编辑、启用停用、调用测试 |
| 本机代理 | 同时提供 Chat Completions、Responses、Anthropic Messages 三类入口；按模型名精确匹配；流式逐事件转发；工具调用可用 |
| 协议转换 | 同一模型在不同协议间自动转换（Responses↔Chat、Chat→Messages、Responses→Messages），网关模型走哪种端点可单独指定；图片输入在三种协议间同样转换 |
| Codex 接入 | 一键写入配置并接入；默认模型、请求地址、模型清单自动生成；模型变化自动同步；可随时断开（只移除自己写入的内容） |
| 上游兼容 | 请求带自有 User-Agent；会话标识自动透传或生成，满足 OpenCode Go 等上游的路由要求 |
| 常驻与自启 | 系统托盘常驻，支持开机启动；双击 EXE 不会弹控制台黑框 |
| 数据自愈 | 配置不一致（默认模型失效、模型指向已删除供应商等）启动时自动修复并提示，不影响使用 |

## 模型命名规则

对外请求名固定为 **`供应商ID/模型ID`**，例如：

```text
aimodelhub/gpt-5.6-sol
deepseek/deepseek-chat
opencode-go/qwen3.8-max
```

- Codex 的模型列表与请求都使用这个名字；同名模型来自不同供应商时不会混淆。
- 兼容写法：直接用供应商名称前缀（如 `DeepSeek/deepseek-chat`）也可以。
- 不带前缀的模型名在**全局唯一**时可用；命中多个供应商会返回"名称歧义"错误并提示改用完整名称。

## 界面一览

| 页面 | 用途 |
|---|---|
| 总览 | 一眼确认代理状态、供应商/模型数量、Codex 接入进度与最近调用 |
| 供应商与模型 | 添加供应商、拉取/管理模型、测试连接与调用 |
| 接入 Codex | 一键接入、默认模型、自动同步开关、高级手动编辑配置 |
| 设置 | 开机启动、启动行为、代理端口、日志、配置目录 |

## 明确不做的事

- 不支持 Claude Code 及其他 Agent 的配置同步（MVP 只做 Codex）。
- 不提供诊断中心、分层检查、配置快照与恢复、路由对象。
- 不开放局域网访问：代理仅监听本机地址。
- 不提供独立的凭据管理模块；供应商密钥保存在本机配置文件中，界面默认脱敏。
- 不导入 cc-switch 等工具的配置（仅参考其交互形式）。
