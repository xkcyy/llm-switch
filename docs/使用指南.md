# 使用指南

| 项目 | 内容 |
|---|---|
| 文档版本 | 1.0 |

| 适用版本 | 0.4.x |
| 适用系统 | Windows 10 / 11 |

## 1. 安装与启动

LLM Switch 是绿色单文件程序，不需要安装：

1. 把 `LLM-Switch.exe` 放到任意目录（建议固定位置，例如 `D:\Tools\LLM-Switch\`）。
2. 双击运行：托盘出现图标，并自动打开管理页 `http://127.0.0.1:8318`。
3. 双击后如果"没反应"，通常是已经在运行了：程序是单实例，会直接打开管理页。

命令行参数（可选）：

```powershell
LLM-Switch.exe --silent     # 静默启动：不打开浏览器，仅托盘常驻（开机启动使用）
LLM-Switch.exe --no-tray    # 调试：不启动托盘
LLM-Switch.exe --version    # 查看版本
```

托盘菜单：打开管理页、启动/停止代理、重启代理、打开配置目录、开机启动、退出。

## 2. 三步完成接入

### 第一步：添加供应商

打开「供应商与模型」→ 右上角「添加供应商」：

1. **选择服务商**（预置地址已按官方文档填好，可改）：

| 服务商 | 默认地址 | 默认协议 |
|---|---|---|
| KmAiModelHub | `https://aimodelhub.ai.kmsoft.com.cn/v1` | Responses |
| OpenCode Go | `https://opencode.ai/zen/go/v1` | Chat（部分模型自动切换，见下） |
| DeepSeek | `https://api.deepseek.com` | Chat |
| OpenAI | `https://api.openai.com/v1` | Responses |
| Anthropic | `https://api.anthropic.com/v1` | Messages |
| 自定义 | 手动填写 | 手动选择 |

2. **粘贴 API Key**（只保存在本机，界面默认脱敏）。
3. 点「保存并测试」：自动测试连接 → 成功后自动拉取模型列表。

> 供应商 ID 会自动按名称生成（如 `deepseek`），它是对外请求名的前缀，可随时修改。

### 第二步：确认模型

拉取成功后弹出模型列表，默认全选：

- 上下文窗口、输出窗口、推理档位能自动补全的会标「自动」，补不到的留空（可稍后手动填）。
- 若上游是**多端点网关**（如 OpenCode Go），「接口协议」列会给出建议（Qwen/MiniMax → messages，Grok/GPT-Luna → responses，其余走供应商默认），导入后仍可修改。
- 点「添加选中的 N 个模型」完成导入。

### 第三步：接入 Codex

打开「接入 Codex」→ 点「一键接入 Codex」：

- 自动写入三处：`%USERPROFILE%\.codex\config.toml`、`auth.json`、`llm-switch-models.json`（模型清单）。
- 只管理自己需要的键，你原有的 Codex 设置（审批策略、项目信任、插件等）不受影响。
- 默认模型自动选第一个可用模型，可在页面上改。
- **自动同步默认开启**：以后新增/删除模型、改默认模型、改代理端口，都会自动更新 Codex 配置。

最后**重启 Codex**（Codex 只在启动时读取配置与模型清单），在模型列表里就能看到 `供应商ID/模型ID` 形式的模型。

## 3. 页面导览

| 页面 | 你能做什么 |
|---|---|
| 总览 | 看代理是否运行、供应商/模型数量、接入进度、最近调用；一键跳到待办步骤 |
| 供应商与模型 | 添加/编辑供应商，查看密钥，测试连接；管理该供应商下的模型（拉取、添加、编辑、启用、测试、删除） |
| 接入 Codex | 一键接入/重新同步/断开；改默认模型；开关自动同步；高级里可手动编辑 config.toml、auth.json |
| 设置 | 开机启动、启动时是否打开控制台、代理端口、日志级别与保留天数、打开配置/日志目录 |

## 4. 常见操作

### 查看或更换密钥

供应商卡片右上角点「密钥 sk…st」→ 编辑弹窗里点右侧眼睛查看完整密钥；直接输入即替换，不改动则保持原值。

### 手动添加或编辑模型

模型列表右上角「手动添加」，或某行的编辑图标。字段说明：

| 字段 | 说明 |
|---|---|
| 模型 ID（上游原始标识） | 填服务商文档里的原始 ID，可包含 `/`（如 `Qwen/Qwen3.6-35B-A3B`） |
| 对外请求名 | 自动生成，等于 `供应商ID/模型ID`，Codex 里用的就是它 |
| 上下文窗口（输入） | 一次能带多少上下文，可点 128K/256K/512K/1M 快捷选择 |
| 最大输出（输出窗口） | 单次回复上限，可点 8K/16K/32K/64K/128K |
| 推理档位 | 如 low/medium/high；可直接输入自定义档位后回车 |
| 接口协议 | 默认跟随供应商；同一网关不同模型走不同端点时单独指定 |

### 测试

- **连接测试**：供应商卡片右上角「测试连接」，失败时会说明是认证、网络、限流、地址还是协议问题。
- **模型调用测试**：模型行上的闪电图标，发一次最小请求并显示耗时。

### 断开 Codex 接入

「接入 Codex」页 →「断开接入」：只移除 LLM Switch 写入的配置，你其他的 Codex 设置保留。

## 5. 数据与隐私

| 项目 | 位置 / 说明 |
|---|---|
| 配置文件 | `%USERPROFILE%\.llm-switch\config.json`（含供应商密钥，明文保存，界面脱敏） |
| 日志 | `%USERPROFILE%\.llm-switch\logs\`（按天滚动，密钥与请求体不落盘） |
| 元数据缓存 | `%USERPROFILE%\.llm-switch\metadata\modelsdev.json` |
| Codex 配置 | `%USERPROFILE%\.codex\config.toml`、`auth.json`、`llm-switch-models.json` |
| 网络访问 | 仅本机回环（代理 8317、管理页 8318）；联网只发生在：请求你配置的供应商、刷新模型元数据（models.dev） |

## 6. 常见问题

| 现象 | 处理 |
|---|---|
| Codex 里看不到新模型 / 改了没生效 | Codex 只在启动时读配置与模型清单，请重启 Codex |
| 调用报 401 或"Invalid API key" | 供应商的 API Key 不正确或为空：到「供应商与模型 → 编辑」重新粘贴 |
| 双击 EXE 没反应 | 通常已经在运行（单实例）：看托盘图标；从托盘菜单打开管理页 |
| 管理页提示"令牌无效" | 管理页令牌每次启动随机生成，请从托盘「打开管理页」进入 |
| 提示端口被占用 | 代理默认 8317、管理页 8318；到设置页改端口（改完会自动同步 Codex） |
| 提示"已自动修复 N 项配置问题" | 启动时发现配置不一致（如默认模型失效、模型指向已删除的供应商）并已自动修复，明细在提示里 |
| 模型信息是空的（—） | 该模型不在公开元数据（models.dev）收录范围内，手动填写即可 |
| 想重来一次 | 退出程序，先复制一份 `%USERPROFILE%\.llm-switch\config.json` 备份，再删除它，重新启动会生成默认配置 |
| 想让 Codex 恢复原样 | 「接入 Codex → 断开接入」，只移除 LLM Switch 写入的内容 |
